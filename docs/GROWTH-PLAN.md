# サイト成長設計（2026年9月時点の分析と方針）

## 1. 現状分析

### 記事の分布（全25本）

| カテゴリ | 本数 | 状態 |
|---|---|---|
| 副業・収益化 | 12 | サイトの中心。収益導線もここに集中 |
| 比較・レビュー | 5 | 1,600〜2,400字の薄い記事が多い。比較記事どうしの重複あり |
| 画像生成AI | 3 | 9月に2本追加し、クラスタとしてつながった |
| ChatGPT | 3 | プロンプト記事が約1,000字と薄い |
| AI動画 | 1 | 記事が1本だけで、カテゴリページとして成立していない |
| Claude | 1 | 同上 |

### 見つかった問題

1. **サイトの打ち出し方と中身が合っていない**：ドメインは `hukugyou.blog`（副業）で、記事の半分は副業テーマ。一方、サイトの説明文は「最新AIツールの使い方・比較」で、大手メディアと正面から競合する位置になっていた。
2. **読者が次の記事に進む道筋がない**：関連記事は「同じカテゴリの新しい順3本」だけ。AI動画・Claudeのように1本しかないカテゴリの記事では、関連記事がまったく出なかった。
3. **カテゴリページが薄い**：記事カードが並ぶだけで説明文がなく、検索エンジンにも読者にも「何のページか」が伝わりにくかった。
4. **パンくずがカテゴリを通っていない**：「ホーム ＞ 記事一覧 ＞ 記事」となっていて、テーマのまとまりが構造化データに現れていなかった。
5. **HTMLの不具合**：`chatgpt-tsukaikata-kanzen-guide` の本文に `# 見出し` があり、ページ内にH1が2つあった。タイトルも「2025年」のままだった。
6. **似たテーマの記事が競合している**：
   - `claude-vs-chatgpt-hikaku-2025` と `chatgpt-claude-fukugyo-hikaku`（ChatGPTとClaudeの比較）
   - `ai-affiliate-marketing-2025` と `ai-blog-fukugyo-hajimekata`（ブログで稼ぐ）
7. **収益化の未設定**：AdSenseの広告枠IDが仮の値（`ARTICLE_TOP` など）のため、本番では広告が出ていない。アフィリエイトも ConoHa・クラウドワークス・ランサーズ・Canvaなどのリンクが未設定。

## 2. 今回実装した構造（コード）

| 変更 | ファイル | 狙い |
|---|---|---|
| 目的別ガイド（5本） | `lib/guides.ts` | 読者の行動順に記事をつなぎ、1人あたりの閲覧記事数と内部リンクを増やす |
| 記事末尾の「ガイドの現在地」と「次に読む」 | `components/GuideNav.tsx` | 読み終えた読者を次の記事へ送る |
| トップとカテゴリのガイド一覧 | `components/GuideList.tsx` | 重要記事をトップから1クリックでたどれるようにする |
| カテゴリページのハブ化 | `app/category/[category]/page.tsx`, `lib/categories.ts` | 紹介文、「まず読みたい記事」、ガイド、CollectionPageの構造化データを追加 |
| 関連記事のスコアリング | `lib/posts.ts` の `getRelatedPosts` | frontmatterの `related`、同じガイド、共通タグ、同じカテゴリの順に重み付け |
| パンくずをカテゴリ経由に | `app/blog/[slug]/page.tsx` | テーマのまとまりを検索エンジンに伝える |
| 打ち出し方の統一 | `app/layout.tsx`, `Header.tsx`, `Footer.tsx` | 「AIで始める副業と、AIツールの使い方」に統一 |
| テスト | `tests/site-structure.test.mjs`, `scripts/verify-site.mjs` | ガイドやカテゴリの設定ミス（存在しない記事など）をCIで検出する |

## 3. 記事を追加するときの手順

1. `content/posts/` に記事を置く（`title` `description` `category` `tags` `image` `date`）。
2. 関連の強いガイドがあれば、`lib/guides.ts` の `steps` の適切な位置に追加する。
3. 特に読ませたい関連記事があれば、frontmatterに `related: ["slug-a", "slug-b"]` を書く。
4. 既存の関連記事から、新しい記事へ本文中のリンクを1〜2本張る。
5. `npm test` と `npm run build` を実行し、`npm run test:site` で表示を確認する。

## 4. コンテンツの優先順位

量産はしない方針を維持します。新しい記事を増やすより、**既存のガイドを完成させる**ことと、**薄い記事を強くする**ことを優先します。

### 優先度A：薄い記事の強化（既存のURLを活かす）

| 記事 | 現状 | やること |
|---|---|---|
| `chatgpt-prompt-engineering-guide` | 約1,000字。2つのガイドに入っている | 修正前後の例、用途別テンプレ、失敗例の表を追加 |
| `claude-tsukaikata-guide` | 約1,800字。Claudeカテゴリの柱記事 | 登録手順、無料と有料の違い（公式で確認）、得意な作業の実例を追加 |
| `ai-douga-seisei-tool` | 約1,700字。AI動画カテゴリの柱記事 | ツールごとの無料範囲・商用条件（公式で確認）、作例の手順を追加 |
| `gemini-vs-chatgpt-hikaku` | 約1,600字 | 比較軸を表で明確にし、用途別の結論を追加 |
| `gazou-seisei-ai-osusume` | 約1,800字。画像生成AIの柱記事 | 各ツールの無料範囲・商用利用条件を公式で確認して追記 |

### 優先度B：重複の解消

- `chatgpt-claude-fukugyo-hikaku` を `claude-vs-chatgpt-hikaku-2025` に統合し、`next.config.js` に301リダイレクトを追加する。
- `ai-affiliate-marketing-2025` は「ブログで稼ぐ」ガイドの最後の記事として残し、内容を「ASPの選び方と紹介記事の書き方」に絞って、`ai-blog-fukugyo-hajimekata` との重複を減らす。

### 優先度C：ガイドの抜けを埋める新しい記事

キーワードの検索数は、Search Consoleやキーワードツールで確認してから着手してください。

| ガイド | 足りない記事の候補 |
|---|---|
| AI副業を安全に始める | 副業が会社にバレる仕組みと住民税の手続き |

| 自分に合うAIを選ぶ | Claudeの料金プラン比較（公式情報で確認できる範囲） |

## 5. 収益化の設定（運営者の作業）

- **AdSense**：管理画面で広告ユニットを作成し、`AdBanner` の `slot` に数値のIDを設定する。これをしないと広告は表示されない。
- **アフィリエイト**：`lib/affiliates.ts` で `url` が空の案件（ConoHa WING、クラウドワークス、ランサーズ、Canva Pro、TechAcademyなど）を提携して埋める。
- **収益に近い記事への案件追加**：確定申告の記事（`ai-fukugyo-kakutei-shinkoku`）は、会計ソフトの案件と相性がよい。提携できたら `affiliates.ts` に追加し、記事に `{{AFF:キー}}` を置く。
- **フッターの表記**：「Amazonアソシエイトに参加しています」と書かれているが、記事内にAmazonのリンクは見当たらない。参加していない場合は表記を削除する。

## 6. 信頼性（E-E-A-T）

- 著者表示は「AIツールナビ編集部」（組織）になっている。実在の運営者のプロフィール（経歴、実際に行った副業、連絡先）を `/about` に載せられると、副業やお金に関わる記事の信頼性が上がる。
- 記事では、実際に試した内容と説明用の例を分けて書く（`ai-blog-koukai-checklist` の方針と同じ）。
- 料金・規約・税制など変わりやすい情報は、確認日を本文に残し、`updated` は実際に見直したときだけ更新する。

## 7. 追う指標（Search Console）

| 指標 | 見る場所 | 目安の使い方 |
|---|---|---|
| インデックス済みページ数 | ページ | 全記事がインデックスされているか。除外された記事は理由を確認 |
| 記事ごとの表示回数と掲載順位 | 検索パフォーマンス | 11〜20位の記事を優先してリライトする |
| クエリ | 検索パフォーマンス | 記事で答えていない検索語があれば、見出しやFAQに追加する |
| ガイド経由の回遊 | アクセス解析（導入する場合） | 「次に読む」のクリック率で、ガイドの順番を見直す |
